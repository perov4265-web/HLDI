# Прошивка контроллера HLDI (Arduino / STM32duino)

Arduino-порт прошивки контроллера лазерной установки прямого экспонирования
HLDI, изначально написанной на C для STM32F103 автором **AlphaCrow**
([форум radiokot](https://www.radiokot.ru/forum/viewtopic.php?t=119089),
[telegram](https://t.me/+NOX32LwJiS83MWQy)).

## Целевое оборудование

Оригинальная прошивка — это **STM32F103** (ARM Cortex-M3, 72 МГц), а не AVR:
исходники (`stm32f103xb.h`, `startup_stm32f10x_md.s`, код работы с регистрами
периферии STM32) не оставляют сомнений. Конструкция опирается на аппаратные
таймеры STM32 и их взаимосвязь:

| Периферия | В оригинале | Роль |
|-----------|-------------|------|
| TIM1   | ШИМ H-моста | двигатель каретки, ПИД-регулятор скорости |
| TIM4   | захват энкодера | позиция каретки, ведущий источник синхронизации |
| TIM2   | ШИМ (4 канала) | лазеры; ведомый от энкодера для попиксельной засветки |
| SysTick| тактирование шагов | шаговый двигатель стола с разгоном/торможением |
| TIM3   | тайм-аут | сторож движения |

Поскольку 8-битный AVR Arduino (Uno/Mega) не способен воспроизвести
синхронизацию энкодер→лазер, скорость и связку из четырёх таймеров, точный
Arduino-таргет — это **STM32F103C8 «Blue Pill»**, собираемый на ядре
[STM32duino](https://github.com/stm32duino/Arduino_Core_STM32) — том же
микроконтроллере, на котором работает оригинал.

## Три сборки

| Папка | Таргет | Назначение |
|-------|--------|------------|
| `HLDI_Firmware/` | STM32F103C8 (STM32duino) | **точный порт** — тот же МК, полный функционал |
| `HLDI_Firmware_AVR/` | Arduino Uno / Nano / Mega | **упрощённое подмножество** для стендовой проверки |
| `HLDI_Firmware_ESP32/` | плата ESP32 | **беспроводная** — связь по WiFi + Bluetooth (BLE) с автопоиском |

Все три используют **один протокол обмена** и общие файлы протокола
(`hldi_protocol.h`, `hldi_proto.h`), поэтому любая из них работает с программой
для ПК без изменений.

### AVR-сборка — осознанное упрощение

Вариант для AVR существует, чтобы можно было поднять связь, погонять оси и
выполнить простые задачи на дешёвом оборудовании. Это **не** замена прошивке
STM32 на реальной установке. По сравнению со сборкой STM32 она:

- управляет кареткой без обратной связи через драйвер STEP/DIR вместо
  замкнутого контура «DC-двигатель + квадратурный энкодер + ПИД»;
- задаёт мощность лазера 8-битным `analogWrite()` вместо центрированного ШИМ
  на 1000 уровней;
- передаёт засветку с фиксированной частотой шага, а не с попиксельной
  синхронизацией по энкодеру.

Карту выводов и полное пояснение см. в `HLDI_Firmware_AVR/hldi_config_avr.h`.

### ESP32-сборка добавляет беспроводную связь

Вариант для ESP32 (`HLDI_Firmware_ESP32/`) сохраняет тот же протокол и
подмножество движения STEP/DIR и добавляет:

- **WiFi**-станцию с **резервной точкой доступа (SoftAP)** и **автоматическим
  переподключением**;
- **TCP**-сервер команд (порт 3333), передающий бинарный протокол;
- **автоматическое обнаружение** — UDP-маяк (порт 50505), который отвечает на
  широковещательные запросы *и* сам объявляет себя каждые несколько секунд;
- **Bluetooth LE** — сервис в стиле Nordic-UART, чтобы ПК мог найти устройство
  и общаться с ним по BLE;
- **настройку WiFi через USB** — небольшую текстовую консоль (введите `help` в
  мониторе порта), реквизиты хранятся в NVS;
- **кольцевой приёмный буфер**, чтобы не терять пакеты при всплесках по любому
  из транспортов.

Программа для ПК находит устройство и подключается к нему автоматически по
WiFi или Bluetooth — протокол обнаружения описан в `docs/PROTOCOL.md`.

Требуется ядро **Arduino-ESP32** (Boards Manager → «esp32»). WiFi и BLE входят
в это ядро; дополнительных библиотек не нужно.

## Карта модулей (оригинал → порт)

| Оригинал на C | Arduino-порт | Содержимое |
|---------------|--------------|------------|
| `hldi.h` | `hldi_protocol.h` | ID команд, структуры `CONFIG`/`SINFO`/`MCUINFO` |
| `hldi.h` (выводы) | `hldi_config.h` | карта выводов + тайминги (выводы STM32duino) |
| `comport.c` + `prot.c` | `hldi_proto.h` | кадрирование пакетов, контрольная сумма, диспетчер команд |
| `motor.c` + `capture.c` | `hldi_motor.h` | DC-двигатель, энкодер, ПИД-регулятор |
| `step.c` + `tab_acc_76k_6000.c` | `hldi_stepper.h` + `hldi_accel_table.h` | шаговик стола + таблица разгона |
| `laser.c` | `hldi_laser.h` | ШИМ лазера + засветка из ОЗУ |
| `hldi.c` (`main`, `tab_cnf`) | `HLDI_Firmware.ino` | setup/loop, конфигурация по умолчанию, диспетчер |

## Сборка

### Arduino IDE
1. Установите ядро **STM32 MCU based boards** (Boards Manager → «STM32»).
2. Откройте `HLDI_Firmware/HLDI_Firmware.ino`.
3. Плата: *Generic STM32F1 series* → *BluePill F103C8*; способ загрузки:
   *STM32CubeProgrammer (SWD)* или *Serial*.
4. Скомпилируйте / загрузите.

### PlatformIO
```bash
cd firmware
pio run -e bluepill_f103c8            # сборка STM32
pio run -e bluepill_f103c8 -t upload  # прошить STM32

pio run -e uno                        # упрощённая AVR-сборка (Uno/Nano)
pio run -e mega -t upload             # прошить Mega

pio run -e esp32dev                   # беспроводная сборка ESP32 (WiFi + BLE)
pio run -e esp32dev -t upload         # прошить ESP32
```

## Отличия от оригинала (и почему)

Порт точно сохраняет протокол и поведение управления. Самые низкоуровневые
обращения к регистрам выражены через API `HardwareTimer` из STM32duino вместо
прямой записи в регистры — это сохраняет тайминги, оставаясь переносимым и
читаемым. Синхронизацию энкодер→лазер, которую оригинал делает целиком в
прерывании захвата TIM4, здесь обеспечивает путь «чтение энкодера + обновление
лазера»; на реальном оборудовании достигается та же попиксельная синхронизация,
а точки расширения (`HldiLaser::flashPixel`) сохранены, чтобы при желании можно
было включить тесную связку через прерывания с прямой настройкой регистров.

Конфигурация по умолчанию (`tab_cnf`) воспроизведена дословно: `kprp=525,
kint=7, kdif=1, kcom=1000, rsx=600, unx=25400, rsy=400, uny=1000, spdx=400,
spdy=3000, nlas=1, qual=1`.
